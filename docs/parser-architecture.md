# 关系中间层与教学树

## 当前数据流

```text
一次模型推理
  → TeachingEvidence（依存 token + Benepar 成分范围）
  → SyntaxRelations（主干候选、修饰边、并列组、从句归属）
  → SyntaxStructure（不可变根描述：索引、角色、结构类型）
  → syntax_assembly（完成结构递归与边界分配）
  → StructuralAnalysis（不可变结构树与边界记录）
  → teaching_projection / teaching_tree（教学标签、卡片组织）
  → TeachingPolicy（独立显示深度）
  → 原有 v4 chunks 协议
```

`syntax_relations.py` 不导入 spaCy、Torch 或服务模块，可独立用不可变证据测试。
关系只引用 token 索引，与卡片是否展开、文本如何合并无关。`analyze_text` 返回
chunks、source tokens 和同一次推理的证据；`parse_text` 保留原来的二元组接口。
语料报告直接复用这些证据，不再为粗卡检测重复调用模型。

## 关系契约

- `edges` 保存依存关系的明确映射，包括主语、宾语、修饰、补足和并列；
  `provenance` 当前为 `spacy-dependency`，不是正确性保证。
- `clauses` 保存从句/非谓语结构的中心候选与直接论元。缺主语可以是合法结构，
  不自动补出省略主语、不将被动施事当主语、不向并列成员复制共享宾语。
- `finiteness` 根据明确词形证据为 `finite`、`nonfinite` 或 `undetermined`；
  裸动词不强行判作非谓语。它不是完整的语气、时态或省略分析器。
- `coordinations` 将依存链上的并列成员归组，但不改变原始挂载边。
- `clause_by_token` 指向沿依存链最近的结构中心；名词性并列不产生新从句。
- `diagnostics` 报告检测到的环，不猜测修复。正常 spaCy 输出应当无环。

## 模块边界与迁移验收

- `server.py` 仅负责模型加载、请求入口与流程编排，不再定义 `chunk_roots`、
  `build_chunks`、`np_expand`、修饰分类或展开判断。
- `syntax_features.py` 保存模型证据判据；`syntax_policy.py` 保存主干角色规则；
  `syntax_structure.py` 负责普通根、修饰根、内嵌从句根及并列提升，返回冻结的
  `SyntaxRoot(index, role, kind)`，没有 `expand` 或显示深度字段。
- `syntax_decomposition.py` 统一决定哪些结构需要递归分析，包含名词、介词、
  从句、同位与补充结构的全部原有递归门控。这是分析分解，不是界面折叠。
- `syntax_assembly.py` 负责边界、归属、特殊构式和完整结构树组装，返回冻结的
  `StructuralAnalysis` / `StructuralNode`。既有倒装、省略、标点补充等规则保留行为，
  但不再与 HTTP 服务或显示策略交织。
- `teaching_projection.py` 通过 `project_structure` 读取结构树的独立副本。
  `TeachingPolicy` 只操作已经生成的卡片，不导入语法模块，不参与边界选择或推理。

结构层不得导入服务或教学层，依赖方向有 AST 测试保护。一次结构分析结果可以被多个
显示策略复用。默认显示不变；`TeachingPolicy(max_depth=0)` 只显示顶层，但不能改变
原始结构、修饰边、并列组或边界决策。实际界面仍使用默认显示，未增加新的设置项。
副本隔离、冻结属性、全部结构类型的递归分派，以及真实句子的不同深度投影均有测试。
真实投影测试还会将分析入口替换为抛错函数，确保显示变化不会偷偷重新解析。

后置分词定语注解通过关系层查询挂载对象。并列分词投影按关系归属生成
平级的完整修饰块；成员范围缺失或子卡跨越两个成员时保持原样，不猜测归属。
非动词成分中完整内嵌的关系从句，可由关系层触发展开，不再完全依赖原先的展开布尔值。
只对中心词、修饰目标及整个从句投影都在当前范围内的关系触发，防止跨边界回收词语。
本轮完成的是旧 builder 的职责迁移和单向依赖隔离，不是删除已有特殊构式规则，
也不承诺关系层能纠正模型本身的误挂载。

## 本地诊断

```bash
uv run --script sidecar/server.py --analyze 'The people waiting outside looked tired.'
```

JSON 输出包含 token、关系、原教学树以及范围选择记录 `boundaryDecisions`。
每条范围记录说明使用 Benepar 兼容范围还是依存连续区间回退，以及候选数量。
这是边界决策追踪，不是全部规则的重写日志，也不是模型置信度。
诊断仅由该命令显式输出到终端，普通 HTTP 请求不输出、不写入日志或修改响应协议。
诊断命令的句子可能保留在 shell 历史中，请勿输入敏感材料。

## 评测与迁移门禁

```bash
python3 -m unittest discover -s sidecar -p 'test_*.py'
uv run --script sidecar/server.py --check-regressions
uv run --script sidecar/server.py --evaluate-relations
cd sidecar && uv run --script tree_snapshot.py
```

真实回归现在同时加载原有 56 项结构回归，以及 `relation_parse_checks.py` 的
12 个固定关系样例，以及并列修饰完整性、嵌套从句主语的专门回归。样例按主干、从句、修饰、并列分类，断言必须存在的关系、
禁止出现的误挂载、主句中心和并列组；包含词汇变体与独立主语反例。
锚词必须在句子中唯一，找不到或重复即失败，不能悄悄匹配第一个词。

这 12 句是开发种子集，不是独立留出集，更不是整体准确率评估。
未经测试的新句子不能因这些样例通过就被宣称准确。完整指标应在独立人工标注集上
分别计算主干正确率、修饰挂载准确率、并列分组准确率与重要结构召回率。
部分关系断言只能验证这些标注目标，不能用于计算全句依存准确率。

## 冻结检查集 v1（2026-09-13）

`relation_holdout.json` 的 16 句及期望在首次评估前冻结，没有根据输出修改答案。
这批句子由助手编写，不是外部人工独立标注，也不代表所有文体或长难句。
检查目标是部分关键关系，不应把通过率标作全句句法准确率。
评估器输出分类计数、每个失败目标和数据集 SHA-256；空集、缺失锚词、重复锚词、
解析异常均不能产生全绿报告。该命令返回非零时不得忽略，手动模型 CI 已接入它。

预提交快照门禁覆盖所有新增结构与投影模块；打包脚本依照 imports 闭包携带它们，
不依赖仓库里的临时路径或旧 builder 的回调。

首次评估结果：解析 16/16、主句中心 16/16、主干关系 23/23、修饰挂载 10/10、
并列边 2/2、并列组 4/4、教学层完整并列短语 1/1，无失败。
数据集 SHA-256：`b485fd0e8fd8e47c4cb97ff371709766099a1b3134f4818ac0d8cc6d0e7dfa21`。
旧行为禁用并列投影时，开发集的两个完整并列修饰测试均失败；启用后均通过。
246 句旧构式快照未变，说明本次改造没有改变这些已冻结的教学树。

本次不切换模型：当前检查没有提供足以支持迁移成本的对照证据。这不是判定现有模型最优。
后续新增构式仍必须通过关系反例、旧 golden 回归与人工审阅的树快照。对明显歧义的句子，
标注多个可接受关系或明确排除该项评分，不把一个解析器的输出直接当作金标准。
只有发现当前模型在留出集上有系统性错误，才进行替代模型对比；当前不添加新模型。
